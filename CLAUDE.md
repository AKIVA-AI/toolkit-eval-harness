# toolkit-eval-harness: agent and contributor notes

Offline scorer: suite (`suite.json` + `cases.jsonl`, directory or zip pack) + predictions
JSONL -> report JSON. Zero runtime dependencies; `cryptography` is an optional extra for
pack signing. Layout: `docs/CODEBASE_MAP.md`. User-facing behavior: `README.md`.

## Commands

| Purpose | Command |
|---|---|
| Install | `pip install -e ".[dev]"` |
| Test | `pytest -q` |
| Coverage gate (CI) | `pytest --cov=src --cov-fail-under=80` |
| Lint | `ruff check .` |
| Type-check | `pyright src/` |

## Conventions

- Scoring must fail closed. A case passes only if every required scorer passes; a missing
  prediction fails; unknown scorers and malformed input raise `ValueError`. Never reintroduce
  "best of" aggregation or silent skips.
- `run` exit codes are part of the public contract (see README "Exit codes"). Change them
  only with a CHANGELOG entry.
- Packs are verified and parsed in memory; do not add code that extracts packs to disk
  during `run`.
- Keep the core stdlib-only. New dependencies go in an optional extra.
- Public names used by downstream code: `toolkit_eval_harness.compare` (`CompareBudget`,
  `compare_reports`), `.report` (`EvalReport`), `.runner` (`run_suite`), `.suite`
  (`EvalSuite`, `EvalCase`, `read_suite_dir`). Keep them importable.
- `docs/report-envelope.md` and `schemas/report-envelope.v1.json` are shared verbatim with the
  other toolkit repos; change them only in all repos at once.
- Never run live model calls in tests: `embedding`/`llm_judge` tests stub `litellm` via
  `sys.modules`. Importer fixtures are generated by the real tools (see their README), never
  hand-edited.
- Tests first for behavior changes; update README and CHANGELOG with them.
